User agent on all four: `… (compatible; Google-Agent; +https://developers.goo…)`. No tool calls.

**`/api/session` proves WebMCP was on in Gemini's browser.** `app.js` stops immediately if `document.modelContext` is missing (`src/page/app.browser.js` line 11). Only when it exists does the script register the tools and then call `GET /api/session` (line 396, to check for an owner sign-in). So each visit's page load followed by `/api/session` means: **the remote browser exposed WebMCP and all 12 public tools were registered**. The 401 just means "no session yet", which is normal for a new visitor.

## What this run tells us

1. **The origin trial reached Gemini's remote browser.** It runs a Chrome recent enough for the token to switch WebMCP on.
2. **Gemini's agent couldn't use the tools.** Its browser controls are visual only (look, scroll, click, type). It correctly worked out that the tools exist but weren't "bridged" to it: "unavailable without new declarations or a browser extension".
3. **Its diagnosis was more accurate than Claude's.** Claude looked for `navigator.modelContext` and concluded WebMCP was off. Gemini didn't claim WebMCP was missing from the browser; it said its own session didn't expose WebMCP tools.
4. **It didn't go around WebMCP.** It ruled out developer tools as "outside the interaction framework" and made no direct server calls, unlike Muse.
5. **It asked permission to use a browser twice** (once per phase), then gave a correct, honest refusal.
6. The Q19 hint (naming `document.modelContext`) would probably **not** have helped Gemini. Its block is its harness, not knowing where to look.

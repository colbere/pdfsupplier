## Findings
1. **D20 confirmed:** with subframe reports accepted, the agent received all six Stripe tools, chose `fill_payment_form` correctly, and supplied every field itself (email, card, expiry, CVC, name, country, postcode).
2. **Hang:** the extension's `executeTabTool` awaited the page tool's reply with **no time limit**. Whatever the reason the reply never came (Stripe's tool not resolving, or the reply getting lost), one silent page tool froze the whole agent.
3. **A second problem found while reviewing the code (not yet hit):** after a navigating tool, the extension asks the frame that ran the tool for a "cross-document result". After `submit_payment`, Stripe redirects the whole tab back to our store, so that Stripe frame no longer exists. The request would have thrown, and the model would have seen an **error for a payment that may have succeeded**.
4. Both are fixed in local patch D21.

## Confirmed by the user afterwards
- **The card details did appear in Stripe's form.** `fill_payment_form` did its work on the page.
- **DevTools → WebMCP showed the `fill_payment_form` call as "In progress".** Stripe's tool never resolved its promise, even though it had filled the form. This is the root cause of the hang, and it is on Stripe's side. D21's 30-second limit turns it into a recoverable error.
- **The user doesn't believe the extension asked "Allow" before `fill_payment_form`.** That is unexpected for a tool that changes the page, unless Stripe marks it `readOnlyHint: true` or an earlier per-site grant covered it. Not verified.

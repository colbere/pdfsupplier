## Findings
1. **End-to-end success with no page clicks.** Every step ran through WebMCP tools: ours, then Stripe's, then ours again.
2. **The confirmation came earlier than planned.** Because the model again got **no tools** right after the navigation (step 4), it asked for approval *before* filling the form. It then used that one "yes" to submit later, without re-asking, and without being able to verify the form, because `fill_payment_form` never returns. The extension's own permission prompt for the consequential `submit_payment` was a second gate. **For the write-up:** an approval given in advance carried over to an action taken after a failed step. The model was open about this ("I submitted anyway, as you'd approved").
3. **The empty tool list after navigation happened again** despite D23's 15-second wait. The model was sent its next request about 5 seconds after `open_checkout`. **Possible reason: the extension wasn't reloaded after D23 was built.** To be checked with the user.
4. **D23's late-results note works** (step 9). **D21's timeout and navigation note work** (steps 4, 6). **D22** (card only) gave 4 Stripe tools and a form with no phone field.
5. **Q5: the PDF was retrieved into the browser's download folder by our `get_download` tool (D19).** The model knows the size and that the file is a valid PDF, but never read its text itself.

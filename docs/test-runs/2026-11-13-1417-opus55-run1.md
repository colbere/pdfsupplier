## Observations
1. **Discovery works without clicking (Q1: yes).** The extension listed `sign_in` with our description, and the agent called it with the code from the prompt. The user reported the side panel showed the tool description exactly as published.
2. **Dynamic tools work (Q12: yes).** Tools registered after `sign_in` were offered to the model on the next request.
3. **Parallel calls:** the model called `get_product` and `create_checkout` in the same turn.
4. **Q2: the agent cannot follow the Stripe link.** This was predicted from the extension's code: no `tabs`/`downloads` permission, and only page tools are given to the model. The model said so plainly and did not invent a way around it.
5. **The agent turned the checkout URL into a clickable link in the side panel** ("Open Stripe Checkout"). That is a person-clickable payment link, the thing rule 3 keeps off our page, now appearing in the agent's UI instead.
6. **The model proposed the fix itself:** "if the Stripe page has its own tools I can use, open it in this tab and I'll fill it in."
7. **Code check after the run:** the extension explicitly supports a tool that navigates or opens a tab: `executeTabTool` in `extension/sidepanel/services/extensionBridge.ts`: "A tool can also open a tab of its own, and the flow then carries on there"; `promptApiBackend.ts`: "when a tool navigated to another page … the turn moves to a new one, with the whole conversation." So a **page tool** that navigates the tab to Stripe should let the agent continue on Stripe's tools.
8. Permission prompts: to be confirmed with the user whether the extension asked "Allow" before `sign_in` / `create_checkout` (expected, since `readOnlyHint: false`).
9. Cost/tokens: the extension's log does not record token usage. Three model requests in total.

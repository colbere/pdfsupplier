## Findings
1. **D21 works as intended:** the navigation note replaced `null`, and the 30-second timeout turned a hang into a recoverable error. The model checked state, retried once, then stopped and asked.
2. **Confirmation behaviour (Q4): good.** The model asked before `submit_payment` and waited for "yes".
3. **New blocker: Stripe Link.** Link's opt-in on hosted Checkout raised a required phone-number field. None of the agent's tools fill it, and `fill_payment_form` never reports what it filled (it never resolves; see run 3). Fixed on our side in D22.
4. **The model was too quick after `submit_payment`:** "Payment submission started" is asynchronous, and the model called `check_order` before the tab had returned to the store. The extension correctly answered "Tool "check_order" is not available on this page."
5. **409 / chat lost: cause not determined.** The server said it had no pending tool call for the incoming tool result, 0.4 s after it answered with the `check_order` call. Code reading did not explain it. Recorded as unexplained. It is in Google's extension server, not ours.

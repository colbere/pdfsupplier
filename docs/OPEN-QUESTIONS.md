| Q1 | Does the extension discover the tools and call them without clicking? | **Answered: yes** | Run 1 (2026-11-13): the side panel listed `sign_in` with our description, and the agent called it with the code from the prompt, then `get_product` and `create_checkout`, with no clicks on the page. | Q2 | Does it follow `create_checkout`'s Stripe link to Stripe's page? If not, what failed exactly, and what would fix it (new tab, embedded Checkout, ...)? | **Answered: no (fix pending user decision)** | Run 1: the agent got the URL but "none of my tools can open or type into the Stripe checkout page". It stopped and offered a clickable link for the user. Cause: the extension has no tabs/navigation ability of its own and only exposes page tools. **But** its code supports a *page tool* that navigates or opens a tab, and then continues the conversation on the new page's tools (`extensionBridge.ts` `executeTabTool` / `onTabChanged`). Candidate fix: a session-protected tool that navigates the tab to the Stripe URL via script (the URL is still never in the DOM). Embedded Checkout would conflict with rule 3. |
| Q3 | Does Stripe's test Checkout page expose WebMCP tools? Which ones? | **Answered (seen in DevTools)** | **Yes, in a sandbox.** On the hosted `cs_test_` page, Chrome 157 DevTools → WebMCP listed six tools (user, 2026-11-13). Their descriptions as shown: `fill_payment_form` ("Fills the payment form with buyer and payment details… call this tool multiple times with new values until the form is ready to submit… may change the order total"), `get_link_pay_token_merchant` ("Get the merchant account identifier for this payment"), `get_order_summary` ("currency, total amount due today, and line items… amounts are in minor units"), `select_payment_method` ("Select a payment method before attempting to fill the form"), `set_link_pay_token` ("Submit a Link Pay Token for this payment"), `submit_payment` ("Submit the checkout form and complete the payment"). Expected flow: `get_order_summary` → `select_payment_method` → `fill_payment_form` (repeat) → `submit_payment`. Annotations (which one has `consequentialHint`) are not yet recorded. Stripe's docs say payment submission carries it. Whether an *agent* uses these tools is still for the agent run. |
| Q4 | Does the agent ask for confirmation before Stripe's consequential submit tool? | Open | Per its README, the extension "always" asks before `consequentialHint: true` tools, even with alerts off. |

| Q13 | Once live, does the design stop other people from spamming the site? (Asked by the user, 2026-11-13.) | Partly answered | **Yes, against:** buying anything; creating Stripe Checkout Sessions (which also blocks "card testing" fraud); and guessing codes (lockout). **No, against:** flooding the page or `sign_in` with requests (volume and cost). The global lockout can also be triggered on purpose to lock the owner out for 15 minutes. **For going live (Phase 2):** Cloudflare rate-limiting rules in front of the Worker, use the real client IP (`CF-Connecting-IP`), and reconsider the global lockout. |
